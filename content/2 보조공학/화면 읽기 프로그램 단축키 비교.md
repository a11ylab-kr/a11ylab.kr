# 개요

화면 읽기 프로그램은 비슷한 일을 서로 다른 명령과 탐색 모델로 수행한다. 같은 `H`가 여러 제품에서 헤딩 이동을 뜻하기도 하지만, 같은 `L`이 어떤 제품에서는 링크이고 다른 제품에서는 목록이기도 한다. 사용자는 제품을 바꿀 때 기능 이름뿐 아니라 손에 익은 키와 현재 탐색 모드를 다시 배워야 한다.

이 문서는 Sense Reader, VoiceWith·NVDA, Windows 내레이터, JAWS, macOS VoiceOver, iPhone VoiceOver, Android TalkBack의 핵심 명령을 **같은 과업 기준으로 비교**한다. 전체 명령 목록은 [[화면 읽기 프로그램 필수 명령과 제스처]]에서 확인할 수 있다.

> [!important] 비교의 한계
> 2026년 8월 3일에 확인한 공식 문서와 Sense Reader 로컬 도움말을 기준으로 작성했다. 제품·운영체제·브라우저 버전, 키보드 배열, 기기 제조사, 제품 등급과 사용자 설정에 따라 명령이 달라질 수 있다. 표에서 칸이 비어 있거나 직접 대응이 없다고 적은 것은 기능이 없다는 뜻이 아니라, 같은 과업에 1:1로 대응하는 기본 명령을 확인하지 못했거나 다른 탐색 모델을 사용한다는 뜻이다.

# 먼저 구분할 탐색 모델

| 제품 | 문서·웹 탐색의 주요 개념 | 앱 자체 키를 사용하기 위한 전환 |
|---|---|---|
| Sense Reader | 가상커서, 브라우저 탭 키 환경과 구형 가상커서 탭 키 환경 | 가상커서 임시 해제 또는 다음 키 전달 |
| VoiceWith·NVDA | 브라우즈 모드와 포커스 모드 | `NVDA+Space` 또는 다음 키 전달 |
| Windows 내레이터 | 스캔 모드 | `내레이터+Space` 또는 다음 키 전달 |
| JAWS | 가상 커서와 Forms Mode | 폼 모드 진입·이탈 또는 다음 키 전달 |
| macOS VoiceOver | VoiceOver 커서, 그룹 상호작용, Quick Nav, 로터 | Quick Nav 끄기, 상호작용 조정, 다음 키 전달 |
| iPhone VoiceOver | VoiceOver 초점, 평면·그룹 탐색, 로터 | 표준 제스처 전달 또는 앱 동작 사용 |
| Android TalkBack | TalkBack 초점, 읽기 제어, 외장 키보드 탐색 모드 | 탐색 모드 전환 또는 패스 스루 |

Windows 제품의 브라우즈 모드·스캔 모드·가상커서는 웹 문서를 선형으로 읽고 요소 사이를 빠르게 이동한다는 점에서 비슷하다. 그러나 자동 전환 조건, 실제 키보드 포커스와 읽기 위치의 관계, 앱 단축키를 통과시키는 방법은 서로 다르다. macOS VoiceOver의 상호작용 모델과 모바일의 터치 탐색을 여기에 억지로 1:1 대응시키면 중요한 차이가 사라진다.

# Windows 제품의 기본 명령 비교

## 시작·종료·도움말

| 과업 | Sense Reader | VoiceWith·NVDA | 내레이터 | JAWS |
|---|---|---|---|---|
| 시작 | `Ctrl+Alt+S` | NVDA는 설치 바로 가기 `Ctrl+Alt+N`; VoiceWith는 앱·바로 가기 실행 | `Windows+Ctrl+Enter` | 시작 메뉴·바로 가기 또는 설치 설정에 따름 |
| 종료 | `Insert+F4` | `NVDA+Q`, `Enter` | `내레이터+Esc` | `Insert+F4` |
| 입력 도움말 | 기능 검색 `Insert+F2` | `NVDA+1` | `내레이터+1` | `Insert+1` |
| 명령 목록·검색 | `Insert+F2` | 입력 도움말·사용자 안내서 | `내레이터+F1` | `Insert+Space`, `J` |
| 현재 포커스 읽기 | `Ctrl+Shift+F` | `NVDA+Tab` | `내레이터+Tab` | `Insert+Tab` |
| 창 제목 읽기 | `Ctrl+Shift+T` | `NVDA+T` | `내레이터+T` | `Insert+T` |
| 읽기 중지 | 연속 읽기 중 `Esc` | `Ctrl` | `Ctrl` | `Ctrl` |

VoiceWith는 NVDA 기반이므로 기본 NVDA 명령을 주로 사용한다. 그러나 고유 HWP 모듈과 수정 사항이 있으므로 같은 버전 번호의 NVDA와 모든 기능이 같다고 보아서는 안 된다.

## 모드 전환과 키 통과

| 과업 | Sense Reader | VoiceWith·NVDA | 내레이터 | JAWS |
|---|---|---|---|---|
| 문서 탐색 모드 전환 | 가상커서 사용 `Ctrl+Shift+F11`, 해제 `Ctrl+Shift+F12` | 브라우즈·포커스 모드 `NVDA+Space` | 스캔 모드 `내레이터+Space` | Forms Mode 진입 `Enter`, 종료 `Num+` |
| 일시적 앱 조작 | 가상커서 임시 해제 Grave 키 | 포커스 모드 또는 자동 전환 | 스캔 모드 끄기 또는 자동 전환 | Forms Mode 또는 자동 전환 |
| 다음 키를 앱에 전달 | 가상커서 `Ctrl+N` | `NVDA+F2` | `내레이터+3` | 숫자열 `Insert+3` |
| 별도 키 환경 전환 | `F9`: 브라우저 탭 키·구형 가상커서 탭 키 | 해당 없음 | 표준·레거시 배열은 설정에서 선택 | 데스크톱·노트북 배열은 설정에서 선택 |

> [!warning] 모드 상태를 기록해야 하는 이유
> 같은 문자 키라도 읽기 모드에서는 헤딩이나 링크로 이동하고, 앱 조작 상태에서는 앱 자체 명령으로 전달될 수 있다. “단축키가 작동하지 않았다”는 기록만으로는 화면 읽기 프로그램이 키를 가로챘는지, 앱이 처리하지 않았는지 알기 어렵다.

# Windows 웹 빠른 탐색 비교

`Shift`를 함께 누르면 이전 요소로 이동한다. 예외와 설정 차이는 제품별 공식 도움말에서 다시 확인해야 한다.

| 과업 | Sense Reader | VoiceWith·NVDA | 내레이터 | JAWS |
|---|---|---|---|---|
| 헤딩 | `H` | `H` | `H` | `H` |
| 헤딩 수준 | `1`~`6` | `1`~`6` | `1`~`9` | `1`~`6` |
| 링크 | `L` | `K` | `K` | 초점 가능한 링크 `Tab`, 링크 목록 `Insert+F7`; 방문 여부별 `U`·`V` |
| 랜드마크·영역 | `J` | `D` | `D` | 다음 영역 `R`, 주 영역 `Q` |
| 편집창 | `F2` | `E` | `E` | `E` |
| 폼 컨트롤 | `N` | `F` | `F` | `F` |
| 버튼 | `N`의 폼 컨트롤 범주 | `B` | `B` | `B` |
| 표 | `T` | `T` | `T` | `T` |
| 목록 | `S` | `L` | `L` | `L` |
| 목록 항목 | `I` | `I` | `I` | `I` |
| 이미지·그래픽 | `.` | `G` | `G` | `G` |
| 체크 상자 | `C`의 체크 컨트롤 범주 | `X` | `X` | `X` |
| 요소 목록 | 링크 `;`, 프레임 `G`, 이미지 `/`, 버튼 `Alt+Num+` | `NVDA+F7` | 링크 `내레이터+F7`, 랜드마크 `내레이터+F5`, 헤딩 `내레이터+F6` | 링크 `Insert+F7`, 헤딩 `Insert+F6`, 폼 `Insert+F5` |

## 공통점

- 헤딩 `H`, 표 `T`, 목록 항목 `I`는 네 계열에서 공통으로 대응한다.
- VoiceWith·NVDA와 최신 내레이터는 링크 `K`, 랜드마크 `D`, 편집창 `E`, 폼 필드 `F`, 버튼 `B`, 목록 `L`, 체크 상자 `X` 등 웹 빠른 탐색 키가 매우 비슷하다.
- `Shift`를 더해 역방향으로 이동하는 규칙도 널리 공유한다.

## 같은 글자지만 뜻이 다른 키

| 키 | Sense Reader | VoiceWith·NVDA·내레이터 | JAWS |
|---|---|---|---|
| `B` | 블록 지정 | 버튼 | 버튼 |
| `C` | 체크 상자·라디오 버튼 묶음 | 콤보 상자 | 콤보 상자·목록 상자·트리뷰 |
| `D` | 필드셋 | 랜드마크 | 다른 유형의 다음 요소 |
| `F` | 프레임 | 폼 필드 | 폼 컨트롤 |
| `G` | 프레임 목록 | 그래픽 | 그래픽 |
| `K` | 방문한 링크 | 링크 | PlaceMarker |
| `L` | 링크 | 목록 | 목록 |
| `N` | 폼 컨트롤 | 링크 묶음 밖 텍스트 | 링크 묶음 건너뛰기 |
| `R` | 폼 컨테이너 | 라디오 버튼 | 영역 |
| `S` | 목록 | 제품별 다른 요소 | 같은 유형의 다음 요소 |
| `X` | 박스 컨트롤 | 체크 상자 | 체크 상자 |

특히 `L`은 Sense Reader에서는 링크, 나머지 세 계열에서는 목록이다. 제품을 오가는 사용자가 가장 쉽게 잘못 누를 수 있는 차이다. Sense Reader의 `B`, `D`, `F`, `G`, `K`, `R`도 다른 제품의 근육 기억을 그대로 적용하면 전혀 다른 기능이 실행된다.

# 텍스트 검토 체계 비교

## 숫자패드가 있는 Windows 환경

| 읽기 단위 | Sense Reader | NVDA 데스크톱 | JAWS 데스크톱 |
|---|---|---|---|
| 이전·현재·다음 줄 | `Num8`·`Num5`·`Num2` | `Num7`·`Num8`·`Num9` | `↑`·`Insert+↑`·`↓` |
| 이전·현재·다음 단어 | `Ctrl+Num4`·`Ctrl+Num5`·`Ctrl+Num6` | `Num4`·`Num5`·`Num6` | `Insert+←`·`Insert+Num5`·`Insert+→` |
| 이전·현재·다음 글자 | `Num4`·`Alt+Num5`·`Num6` | `Num1`·`Num2`·`Num3` | `←`·`Num5`·`→` |
| 연속 읽기 | `F11` | 시스템 캐럿 `NVDA+↓`, 검토 커서 `Num+` | `Insert+↓` |

NVDA는 숫자패드의 3×3 배열을 줄·단어·글자 층으로 사용한다. Sense Reader는 세로 `8·5·2`를 줄에 배치하고 가로 `4·5·6`에 보조 키를 더해 단어와 글자를 구분한다. 같은 숫자패드를 사용해도 손의 이동 패턴이 달라 전환 비용이 크다.

내레이터 표준 배열은 `내레이터+U·I·O`를 줄, `내레이터+J·K·L`을 단어, `내레이터+M·,·.`을 글자 읽기에 사용한다. 숫자패드만 놓고 다른 제품과 비교하기보다 표준 배열의 3×3 문자 배치를 함께 보아야 한다.

# macOS VoiceOver와 Windows 제품 비교

| Windows에서 하려는 과업 | macOS VoiceOver의 주요 방법 |
|---|---|
| 다음·이전 항목 | `VO+→` / `VO+←` |
| 현재 항목 실행 | `VO+Space` |
| 복합 영역 안으로 들어가기 | `VO+Shift+↓`로 상호작용 시작 |
| 복합 영역에서 나오기 | `VO+Shift+↑`; 최상위는 `VO+Shift+Esc` |
| 헤딩·링크·표 목록 열기 | `VO+U` 로터 |
| 단일 문자로 웹 요소 탐색 | `VO+Q`로 단일 문자 Quick Nav를 켠 뒤 할당된 키 사용 |
| 화살표만으로 탐색 | `VO+Shift+Q`로 화살표 Quick Nav 전환 |
| 웹 앱의 다음 키를 그대로 사용 | `VO+Tab` 뒤에 해당 키 입력 |

Windows의 브라우즈 모드와 macOS VoiceOver의 Quick Nav는 빠른 웹 탐색을 제공한다는 점에서는 비슷하다. 그러나 VoiceOver는 VoiceOver 커서와 실제 키보드 포커스, 그룹 상호작용, Quick Nav 상태를 함께 관리한다. 그러므로 “VoiceOver에는 가상커서가 없다”거나 “Quick Nav가 NVDA 브라우즈 모드와 같다”는 한 문장으로 설명하기 어렵다.

# 모바일 터치 제스처 비교

## TalkBack과 iPhone VoiceOver

| 과업 | Android TalkBack | iPhone VoiceOver |
|---|---|---|
| 손가락 아래 항목 듣기 | 한 손가락으로 화면 탐색 | 한 손가락으로 화면 탐색 |
| 다음·이전 항목 | 한 손가락 오른쪽 / 왼쪽 쓸기 | 한 손가락 오른쪽 / 왼쪽 쓸기 |
| 선택한 항목 실행 | 한 손가락 두 번 탭 | 한 손가락 두 번 탭 |
| 아래쪽 내용 보기 | 두 손가락 위로 쓸기 | 세 손가락 위로 쓸기 |
| 위쪽 내용 보기 | 두 손가락 아래로 쓸기 | 세 손가락 아래로 쓸기 |
| 읽기 일시 정지·계속 | 두 손가락 한 번 탭 | 두 손가락 한 번 탭 |
| 현재 위치부터 연속 읽기 | 두 손가락 세 번 탭 | 두 손가락 아래로 쓸기 |
| 읽기 단위 선택 | 세 손가락 위·아래 쓸기 또는 꺾기 제스처 | 두 손가락으로 로터 돌리기 |
| 이전 화면 | 아래로 쓸고 왼쪽으로 쓸기 | 두 손가락으로 Z 모양 문지르기 또는 뒤로 버튼 |
| 다음 표준 동작 전달 | 네 손가락 두 번 탭한 뒤 길게 누르기 | 두 번 탭한 뒤 길게 누르고 표준 제스처 수행 |

두 제품 모두 한 손가락 좌우 쓸기와 두 번 탭으로 기본 탐색을 시작한다. 그러나 화면 스크롤은 TalkBack이 두 손가락, VoiceOver가 세 손가락이다. 읽기 단위도 TalkBack의 읽기 제어와 VoiceOver의 로터라는 서로 다른 개념을 사용한다.

## 외장 키보드까지 포함하면

- TalkBack 16.2 이상은 향상된 키맵과 탐색 모드를 제공한다. 새 활성화에서는 향상된 키맵이 기본이지만 이전 설치와 사용자 설정은 다를 수 있다.
- iPhone·iPad VoiceOver도 외장 키보드 명령을 제공하며 `VO` 보조 키, Quick Nav와 로터 개념을 사용한다.
- 터치 제스처를 안다는 이유만으로 외장 키보드 조작까지 안다고 볼 수 없다. 같은 모바일 화면 읽기 프로그램 안에서도 입력 방식이 바뀌면 별도의 숙련이 필요하다.

# 전환 학습에서 먼저 확인할 것

## Sense Reader에서 VoiceWith·NVDA·내레이터로 바꿀 때

1. 링크가 `L`에서 `K`로 바뀐다.
2. 목록이 `S`에서 `L`로 바뀐다.
3. 랜드마크가 `J`에서 `D`로 바뀐다.
4. 편집창이 `F2`에서 `E`로 바뀐다.
5. 폼 컨트롤이 `N`에서 `F`로 바뀐다.
6. `B`, `D`, `F`, `G`, `K`, `L`, `R`, `X`처럼 같은 글자의 의미가 달라지는 키를 먼저 연습한다.

## Windows에서 macOS VoiceOver로 바꿀 때

1. 브라우즈·포커스 모드보다 VoiceOver 커서와 그룹 상호작용 상태를 먼저 확인한다.
2. `VO+Shift+↓`와 `VO+Shift+↑`로 그룹에 들어가고 나오는 흐름을 익힌다.
3. `VO+U` 로터와 Quick Nav의 켜짐 상태를 구분한다.
4. 웹 앱 단축키가 충돌할 때 `VO+Tab`으로 다음 키를 전달한다.

## PC에서 스마트폰으로 바꿀 때

1. 실제 키보드 포커스 대신 손가락 아래의 접근성 초점과 순차 탐색을 익힌다.
2. 실행은 두 번 탭으로 비슷하지만 스크롤 손가락 수는 제품마다 다르다.
3. 문서 요소 이동은 문자 키 대신 TalkBack 읽기 제어나 VoiceOver 로터를 사용한다.
4. 홈·뒤로·앱 전환·알림처럼 운영체제 이동 제스처를 함께 익힌다.

# 접근성 평가에 주는 의미

단축키가 존재한다는 사실만으로 접근 가능하다고 판단할 수 없다. 실제 평가에서는 다음을 함께 기록해야 한다.

- 운영체제와 빌드
- 브라우저 또는 앱과 버전
- 화면 읽기 프로그램의 버전·에디션·키보드 배열
- 브라우즈 모드·스캔 모드·가상커서·Quick Nav·TalkBack 탐색 모드의 상태
- 수행한 과업과 진입·조작·이탈·오류 복구 결과
- 읽기 위치와 실제 포커스가 어긋났는지
- 앱 단축키를 사용하기 위해 별도 키 통과가 필요했는지
- 숙련자만 우회할 수 있었는지, 처음 쓰는 사용자도 방법을 발견할 수 있었는지

제품별 단축키 차이는 단순한 암기 문제가 아니다. 모드 상태와 포커스를 추적하고, 같은 과업을 다른 방식으로 다시 배우며, 오류가 생겼을 때 현재 위치를 복구해야 하는 인지적·운동적 비용이다. 이 비용은 [[접근성 브리핑 제22호]]에서 다룬 화면 읽기 프로그램 파편화의 한 사례다.
