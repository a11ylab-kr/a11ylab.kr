accessibility.

# 개요

접근성은 가능한 많은 사람이 제품, 서비스, 공간, 정보, 기술을 불편 없이 이용하고 참여할 수 있도록 설계하고 제공하며 평가할 때 쓰는 말이다. 웹 접근성의 맥락에서는 장애가 있는 사람이 웹사이트, 도구, 기술을 인식하고, 이해하고, 탐색하고, 상호작용하고, 콘텐츠를 만들 수 있도록 보장하는 것을 뜻한다.[^1]

접근성은 단순히 “장애인을 위한 특별한 기능”을 덧붙이는 일이 아니다. 처음부터 다양한 몸, 감각, 인지 방식, 사용 환경을 고려해 배제되는 사용자를 줄이는 설계 원칙이다. 그래서 접근성은 기술 문제이면서 동시에 권리, 사용성, 교육, 정보 접근, 사회 참여의 문제이기도 하다.

# 접근성이 필요한 이유

접근성은 특히 장애가 있는 사람에게 필수적이다. 하지만 접근성 개선의 효과는 장애인에게만 머물지 않는다. 충분한 색 대비는 저시력 사용자뿐 아니라 밝은 햇빛 아래에서 휴대전화를 보는 사람에게도 도움이 되고, 자막은 청각장애인뿐 아니라 소리를 켤 수 없는 환경의 사용자에게도 도움이 된다. 명확한 제목 구조, 일관된 탐색, 쉬운 안내 문장은 처음 방문한 사용자나 문해력이 낮은 사용자에게도 중요하다.[^2]

W3C WAI는 웹이 교육, 고용, 정부, 상거래, 의료, 여가, 일상적 의사소통과 참여에 점점 더 중요해지고 있다고 설명한다. 따라서 접근 가능한 웹은 다양한 능력을 가진 사람에게 동등한 접근과 동등한 기회를 제공하는 조건이다.[^1]

# 접근성과 사용성, 포용

접근성, 사용성, 포용은 서로 겹치지만 완전히 같은 말은 아니다. 사용성은 특정 사용자가 특정 맥락에서 목표를 효과적이고 효율적이며 만족스럽게 달성할 수 있는지를 본다. 포용은 더 넓게 다양성과 참여를 다루며, 언어, 지역, 경제 상황, 교육 수준, 기기와 네트워크 환경 같은 조건까지 함께 본다.

접근성은 그중에서도 장애와 관련된 차별적 장벽을 없애고 장애가 있는 사람에게 동등한 사용자 경험을 제공하는 데 초점을 둔다. 따라서 포용적 설계를 말할 때도 장애 관련 장벽을 흐리게 만들지 않는 것이 중요하다.[^3]

# 웹 접근성의 기본 관점

웹 접근성은 여러 층에서 함께 다뤄야 한다.

- 콘텐츠: 제목, 링크 이름, 대체 텍스트, 쉬운 설명, 문서 구조
- 시각 디자인: 색 대비, 글자 크기, 간격, 확대 시 레이아웃
- 상호작용: 키보드 조작, 포커스 표시, 오류 안내, 시간 제한
- 기술 구조: HTML 의미, [[ARIA]], landmark, 폼 라벨, heading level
- [[보조공학기술]] 호환성: [[화면 읽기 프로그램]], 화면 확대, 음성 입력 등과의 동작
- 운영: 개발 초기부터 점검하고, 배포 후에도 사용자 피드백과 재검사를 반복하는 과정

자동 검사 도구는 접근성 문제를 찾는 데 도움이 되지만, 도구만으로 접근성을 완전히 판정할 수는 없다. W3C WAI도 평가 도구가 문제를 식별하는 데 도움을 줄 수 있지만, 어떤 도구도 단독으로 사이트가 접근성 지침을 충족하는지 결정할 수는 없다고 설명한다. 자동 검사, 수동 테스트, 전문가 평가, 실제 사용자 경험 확인이 함께 필요하다.[^1]
